# Qryptana Android Screen & State Inventory

## Executive Overview

This inventory covers the entire user-visible Android application for Qryptana, tracing navigation hierarchies, entry points, shared Compose Multiplatform versus Android-specific implementations, current styling dependencies, observed UX/visual issues with repository evidence, proposed design treatments across themes, and verification methods.

### Platform Boundary & Shared Compose Architecture
Qryptana shares substantial UI between Android and Desktop via Compose Multiplatform in `apps/multiplatform/common/src/commonMain/kotlin/`. However, any modification in `commonMain` directly risks impacting desktop and potential iOS builds unless guarded by:
1. Platform checks (`if (appPlatform.isAndroid) ...`),
2. Expect/actual declarations (`PlatformTextField`, `BackHandler`, `AppearanceView`, etc.), or
3. Platform-scoped palette/theme delegation (e.g. `ThemeDefaults.androidPalette()` vs `ThemeDefaults.darkPalette(isDesktop = true)`).

In this inventory, each surface is explicitly categorized by implementation boundary so future changes can be safely implemented without regressing Desktop or iOS.

## Analysis of Discovered UX & Visual Gaps

### 1. Legacy Warm Brown / Tan Message Bubbles
The single most glaring visual defect in the current Android implementation is that sent message bubbles are configured as `#3A2B24` (warm dark brown) in Dark mode and `#F1DFD3` (warm peach) in Light mode, with quote backgrounds at `#4A3428` and `#E7C6B0`. This contradicts the visual direction:
- *"Avoid: Brown, tan, beige, or orange-tinted backgrounds."*
- *"Cool charcoal and titanium foundations. Silver typography and structural details. Restrained, authentic copper accents."*
Sent messages must be transitioned to **Cool Raised Titanium `#1E232A`** (dark) and **Cool Silver `#E1E5EA`** (light) with copper reserved exclusively for delivery status marks or subtle metadata accents.

### 2. Missing Touch Target Standards (48dp Rule)
Multiple shared components (`SimpleButtonFrame`, `SectionItemView`, icon buttons in `ImageFullScreenView`, and clear buttons in `SearchTextField`) currently use 8dp vertical padding without asserting a minimum height constraint. On physical Android touch screens, this produces interactive targets between 36dp and 40dp, violating the Android 48dp minimum touch target requirement.

### 3. Logo Treatment Integrity
The canonical Qryptana logo assets exist in `docs/qryptana/brand/` as:
- `qryptana-symbol.png` (1254x1254, RGBA)
- `qryptana-wordmark.png` (1672x941, RGBA)
Earlier iterations attempted to apply a gradient shader or metallic filter directly over the wordmark alpha mask in Compose. This was rejected because the logo is approved brand artwork that must not be redrawn, tinted, recolored, or shaded. Both Android and Desktop must display the canonical PNG assets directly.

### 4. Smart Invite Sweep Gradient Inconsistency
While `QryptanaAndroidSmartInvite` in `QRCode.kt` was successfully refined into a cool titanium card with a high-contrast black-on-white QR, the fallback `branded` code path in lines 186–204 of `QRCode.kt` still contains an obsolete sweep gradient referencing cyan (`#6FE7FF`) and purple (`#9B7BFF`). This fallback must be permanently guarded or removed so non-titanium colors can never appear on Android.
